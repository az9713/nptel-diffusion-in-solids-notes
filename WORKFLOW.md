# Lecture-note production workflow

This project follows the inspected Human Physiology production workflow, NPTEL
predictive-modelling and quantum-computation repositories, and Stanford CS229
reading edition. Their prior validation does not validate this course.

1. Match supplied playlist entries to official NPTEL lesson IDs. Preserve upload
   positions separately. Record introductions, tutorials, missing/extra entries,
   source dates, duration, caption type, hashes, and acquisition failures.
2. Read timestamped source text sequentially. Inspect selected source frames for
   ambiguous equations, experimental plots, or software demonstrations. Separate
   sampled visual verification from complete audiovisual review.
3. Specify reader, scope, notation, dependencies, exact section results, running
   problems, code checks, exercises, and useful visuals before drafting. Perform
   an independent plan review and repair its findings.
4. Calibrate against representative complete reference chapters. Develop one
   representative chapter through all passes before scaling. Draft sections
   directly in HTML: source coverage, developed prose, mathematics, primary-source
   research, implementation, exercises, prose editing, depth comparison, checks.
5. Derive continuum transport, microscopic jumps, thermodynamic driving forces,
   inverse measurements, and material-specific mechanisms with explicit models.
   Preserve distinctions among tracer, intrinsic, chemical, and interdiffusion
   coefficients. Compute every printed numerical construction. Proprietary
   software demonstrations may be explained and complemented by clearly scoped
   Python models; never claim a DICTRA reproduction without executing DICTRA.
6. Use deterministic controlled motion for time evolution when it teaches the
   phenomenon. Provide seeking/playback, reduced motion, textual interpretation,
   and print alternatives. Verify initial/intermediate/final states and controls.
7. Obtain two independent full science-editor reviews per chapter, bound to the
   actual fragment/code/asset hashes. Repair blockers and perform targeted checks
   on repairs. Scientific acceptance does not imply source or visual completeness.
8. Build the portable dark HTML reader with local MathJax, chapter navigation,
   search, study guide, source map, references, and runnable laboratories. Check
   mathematics, anchors, links, numerical outputs, desktop/mobile rendering,
   accessible controls, reduced motion, printing, and source-free rebuilds.
9. Publish only the accepted complete reader and reproducible public inputs. Keep
   raw sources and private work ignored. Inspect staging, commit, push to the
   user's course repository, and verify remote commit and live reader separately.

Authorization for autonomous completion and GitHub publication comes from the
current user request. No personal author approvals or human certification are
implied. Actual evidence is recorded in completion.json and validation/.
